# v0.6 feature evidence and boundaries

All 22 roadmap areas have concrete CLI/module mechanisms. The table separates those mechanisms from the available acceptance evidence and dependencies. Automated test filenames describe coverage; release execution totals are recorded separately. A model reply, provider configuration or defined CI job is not evidence that every external capability works.

The actual Linux x64 PTY run used Node v24.19.0 and unchanged Codex 0.160.1, with isolated HOME/XDG/state/project, a loopback Chat Completions provider, 22 native streamed requests, zero offline model calls and four CLI exits of 0. It exercised native tools, files, checks, saved state, multiline/literal paste input, model metadata reset and failed-connection offline recovery rather than mocking the CLI or engine. See [terminal evidence](v0.6-terminal-evidence.md). Windows/Linux automated execution is local; macOS/ARM CI is defined but has not run here.

Separate scoped sandbox/background validation passed 23 tests with 5 platform skips on Windows and 27 with 1 skip on root Linux, 28 total per host. Linux native checks denied out-of-scope writes, networking and synthetic host credentials, and enforced read-only scope. Windows checks safely blocked an outside write or refused the entire check. Those results are distinct from the PTY's explicitly unrestricted full-scope file/check sequence and from complete release-suite totals.

## CI definition

The six labels in [`.github/workflows/test.yml`](../.github/workflows/test.yml) are `ubuntu-24.04`, `ubuntu-24.04-arm`, `windows-2025`, `windows-11-arm`, `macos-15-intel` and `macos-15`. GitHub documents these as x64/ARM64 runner pairs and documents Unix passwordless sudo plus Windows administrator runners. The workflow verifies `process.arch`, uses Node 24, installs the pinned native engine, runs `doctor`, then runs the tests under the platform's required admission. [GitHub-hosted runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

The workflow uses the official current `actions/checkout@v7` and `actions/setup-node@v7` examples, read-only repository permissions, no persisted checkout credential and no automatic package-manager cache. [Checkout documentation](https://github.com/actions/checkout), [setup-node documentation](https://github.com/actions/setup-node). No remote run or additional architecture result is implied by committing this definition.
