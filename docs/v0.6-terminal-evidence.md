# v0.6 native terminal acceptance

The reproducible acceptance runner is `test/manual/verify-v0.6-linux.py`. It uses Python's standard library to operate a real Linux PTY, launch the product CLI, and exercise the installed native Codex engine. A local HTTP server supplies valid Chat Completions SSE responses, usage records, and native tool calls. The terminal UI, engine, bridge, project files, checks, checkpoints, chat storage, and budget ledger run normally.

Run from the product directory as Linux root, with Node >=22 and the matching Linux runtime installed:

```sh
python3 -B test/manual/verify-v0.6-linux.py --output-directory /tmp/v0.6-proof
```

The runner creates a temporary project and private HOME, XDG configuration/data/state/cache/runtime directories, TMPDIR and application state. It supplies only a synthetic API key and the loopback provider. The original desktop Codex home and application state are outside the test. Every CLI child is closed after the run, and the temporary project/state directories are removed.

Retained evidence includes `terminal-v0.6-linux-result.json`, `terminal-v0.6-linux.log`, and `terminal-v0.6-linux-requests.json`. Credentials and temporary isolation paths are redacted. A failed run saves corresponding `failure` artifacts and exits nonzero. The normalized transcript removes sticky-header save/restore redraw blocks that can occur between streamed response fragments; the failure ANSI log preserves sanitized raw control sequences for diagnosis.

The assertions cover:

- Default offline shell, help, status, saved-chat listing and approved project memory, with zero model requests.
- Guided `/connect`, explicit launch flags, streamed native answers, the 4096-token output cap, selected AI display and per-message AI attribution. Switching models clears the prior model's capability declarations, context capacity and supported effort metadata before a new capacity is declared.
- Ordinary multiline `/prompt`, bracketed multiline paste inside `/prompt`, idle bracketed paste and busy bracketed paste followed by Enter reach the model literally without hanging or changing Ask permissions. Embedded newlines survive the multiline paste; a leading `/permissions allow-everything` remains prompt text.
- Invalid automatic connection settings (a model containing a control character and a malformed base URL) report the failure and continue offline, with saved-chat listing/open/history available and no model traffic.
- Approved project memory in native developer instructions. The Chat Completions bridge maps that instruction role to `system`; conversation replay remains `user` input.
- Native command tool writes to actual project files, recorded before/after changes, zero-check Needs review, passing and failing explicit checks, full undo, and conflict-aware preservation of later human edits.
- Workflow instructions and separate planner/reviewer native sessions operating on disposable bounded source snapshots. Their reports remain advisory and unverified.
- Independent saved chats, reopening the original chat, restart continuation, and exclusion of the unrelated chat from replay.
- Over-capacity replay rejected before provider traffic, a reviewed bounded summary/selection replayed as conversation, later messages retained through another reconnect, and `/clear` creating fresh engine context while retaining the complete visible archive.
- A one-request daily budget blocking the next turn before provider traffic, with usage and configured pricing recorded by the local ledger.
- Normal terminal exit, alternate-screen/scroll-region restoration and no synthetic credential printed or persisted in JSON state.

This test does not establish physical microphone/speaker behavior, actual GPU provisioning or billing, a paid provider's model/tool/vision capabilities, macOS execution, Windows elevation/sandbox behavior, OS startup installation, real browser actions, or provider tokenization and billing accuracy. Its fixture token usage is deliberately deterministic. Separate hardware/provider/platform acceptance is required for those claims.

The PTY's explicit file/check/undo sequence selects full scope, Allow Everything and Web On, so those particular checks use the explicitly unrestricted policy. Separate native sandbox tests establish Linux out-of-scope write/network/credential denial and read-only enforcement; Windows tests require an outside write to be blocked or the entire restricted check to be refused. The [feature evidence](v0.6-feature-evidence.md) records that separate scope, rather than attributing it to this PTY sequence.

The earlier `verify-terminal-linux.py` runner retains its v0.5 assumptions. Its voice approval probe deliberately requests an unsandboxed command. Under the v0.6 default project scope/Web Off policy that approval is denied before a typed prompt is shown; that earlier probe needs an explicit full scope and Web On setup to continue testing typed approval. The v0.6 runner does not claim that this older script has passed unchanged.
