# Conversation history, handoffs, and local network measurements

`createChatHistory({ secrets: () => currentSecrets })` holds only visible user and assistant messages in memory. The caller records task prompts with `addUser(text, { model, attachments })`; CLI commands and hidden reasoning are excluded. Messages remain available across model switches, permission changes, and `/clear`. Only an explicit `/history clear` calls `clear()`.

Assistant integration uses `beginAssistant(id, { model })`, `appendAssistant(id, delta, { model })`, and `finishAssistant(id, completedText, { model })`. Use a thread-prefixed identifier, such as `${threadId}:${itemId}`. Completion replaces accumulated deltas with the final full text; repeated completion remains one message. An interrupted message keeps all text already received. Empty assistant placeholders are omitted from exports.

`snapshot()` returns `{ version: 1, messages }`. Each message contains its identifier, role, model name (or `null`), and full text. Assistant entries also carry streaming/completed status. Attachment entries retain names, paths, media types, dimensions, sizes, and frame/page counts when supplied; file bytes, buffers, and provider payloads are excluded. Text preserves Unicode, code, blank lines, and trailing whitespace after the same credential and terminal-control filtering used for visible output. Connection keys from previous models remain known in memory so later exports still mask them.

`toPrompt()` produces complete sanitized JSON transcript context for a newly selected model. It does not summarize, truncate, or call a model. Attachment metadata does not substitute for reattaching original files. The caller must handle the new model's context limit; this helper never silently shortens the conversation.

The explicit `/handoff` command calls `await exportHandoff({ directory, cwd, title })`. With no directory, files go under `cwd/.sudocli/handoffs`. It returns `{ jsonPath, markdownPath, messageCount }`, using unique filenames and restricted file modes where supported. JSON is the canonical full transcript. Markdown includes every message in chronological order, with literal text fences long enough to preserve code fences inside messages. Creating history, recording messages, or switching models causes no automatic chat-file writes. Existing exports remain unchanged when memory is cleared.

`createNetworkStatus({ platform, sampler, clock, intervalMs: 1000 })` provides `await start()`, `await sample()`, synchronous `snapshot()`, and `stop()`. The default sampler reads local interface information only. Inject a sampler returning `{ supported, interfaces: [{ id, name, wifi: true|false|null, connected: true|false|null, rxBytes, txBytes }] }` for tests. Byte counters may be decimal strings to retain 64-bit precision. The snapshot contains `wifi` (`Yes`, `No`, or `Unknown`), `downloadBps`, `uploadBps`, interface descriptions, measurement source, and monotonic sample time.

Rates are current bytes per second from cumulative receive/transmit counter differences over actual elapsed time. They are not the maximum link speed or a paid bandwidth test. Rates remain unknown until a second valid sample; counter resets and new/reconnected interfaces restart baselines. Unsupported tools, permission failures, malformed data, and ambiguous Wi-Fi classification remain unknown. Ethernet connectivity never proves Wi-Fi connectivity. OS-visible physical interfaces are counted once; virtual adapter duplication and loopback are excluded. In a VM or WSL, the monitor reports guest interfaces and cannot infer the host's Wi-Fi connection. Web Access Off does not disable these local read-only measurements, and no remote connection is created to measure them.

Windows sampling uses hidden, noninteractive PowerShell with `Get-NetAdapter` and `Get-NetAdapterStatistics`. Actual WLAN interface/physical-medium identifiers distinguish Wi-Fi from Ethernet; receive/transmit counters are read as decimal strings. The adapter counters are supplied by [Microsoft's NetAdapter statistics API](https://learn.microsoft.com/en-us/powershell/module/netadapter/get-netadapterstatistics), and WLAN medium identifiers are documented in [Microsoft's physical medium definitions](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/oid-gen-physical-medium).

Linux reads `/sys/class/net`, wireless/phy80211 markers, link state, and `statistics/rx_bytes` / `tx_bytes`. These cumulative counters follow the [Linux kernel interface statistics documentation](https://www.kernel.org/doc/html/latest/networking/statistics.html).

macOS maps hardware ports to interface names using `networksetup -listallhardwareports`, confirms link state with `ifconfig`, and reads one link-layer row per interface from `netstat -ibn`. Apple explicitly documents that Wi-Fi may be `en1` while Ethernet is `en0`, so interface names alone are insufficient. See [Apple's interface identification guidance](https://developer.apple.com/documentation/network/recording-a-packet-trace) and [Apple's netstat manual source](https://github.com/apple-oss-distributions/network_cmds/blob/main/netstat.tproj/netstat.1). Native macOS execution still requires a macOS runner; fixture parsing is covered by the test suite.
