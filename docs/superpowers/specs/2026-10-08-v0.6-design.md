# SUDO CLI 0.6 design

The user approved the complete improvement roadmap on 8 October 2026. Implement it in the existing terminal application, without changing the Codex desktop app. Preserve administrator/root admission, the red SUDO CLI identity, credits, and every antenna character, colour and timing value.

## Acceptance and changes

Every task gets a bounded workspace checkpoint. `/changes` reviews actual file changes; `/undo` restores only files still matching the recorded AI result and reports human-edit conflicts. `/verify` executes explicit user-selected checks and shows Verified, Needs review or Failed. A model finishing a turn never proves success. `/workflow` selects plan, edit, test or review guidance; an independent reviewer uses a disposable source snapshot. Defensive `/security` scans local sources, dependencies and credential patterns without revealing secrets; approved local review targets can be copied to a bounded isolated lab.

## Permissions, budgets and operations

Administrator admission is separate from agent permission. Add project/read-only/full scopes, narrow approval decisions, isolated child environments, and fail-closed Web Off native sandboxing. Never call a mode a firewall when unsupported; refuse unsafe combinations rather than imply enforcement. Budget hooks operate before every provider request, reserving bounded estimated usage and accounting actual usage where reported. Task and day money/token/request/duration caps reject work when exhausted. Missing pricing cannot satisfy a money cap. Voice, training and hourly GPU fees are separately identified.

GPU wake/sleep acknowledgement is distinct from verified provider state. Optional status hooks must explicitly report execution/billing state. Persistent schedules enqueue each occurrence once; interrupted actions require review. Explicit OS autostart installation has no plaintext credentials and never happens at startup implicitly. Computer sleep/off still stops local work.

## Models and context

Start at a usable shell before model configuration so saved chats remain accessible offline. Guided cloud/local selection, model discovery and bounded connection tests run at runtime. Show selected model before its first response, with connection confirmation separately. Optional OS credential protection supplements the RAM-only default. Capability reports distinguish observed, declared and unknown facts. Unsupported declared features are refused; unknown support is labelled. Stream Chat Completions incrementally. Show measured first-response latency, errors and generation speed; the existing connection percentage is an optional estimate. Label interface throughput Live Traffic.

The full transcript stays archived. Context preflight bounds requests against a declared capacity, marks token estimation, and never silently truncates. User-reviewed summaries and relevant excerpts permit long conversations. Editable project memory contains only user-approved rules/decisions/preferences. Optional local/cheap routing has a manual override and explicit rationale.

## Voice, usability and adapters

Clear-reading mode favours short lines, answer first, spaced actions, optional speech and expandable detail. Search commands and chat history. Multi-line prompt input and safe bracketed paste support code. Live voice gains configurable wake phrase, pause/resume/repeat, device discovery and echo-avoidance controls; acoustic echo cancellation and physical hardware must remain explicitly unverified unless actually available and tested.

Provide a concrete dedicated Chromium/CDP browser MCP adapter with scoped origins, visible actions and immediate stop. Native desktop adapters require an explicitly connected service and tested capability discovery. Guided search uses supported hosted search or configured search MCP and preserves source URLs, treating fetched instructions as untrusted. Training stays in the advanced menu and requires a supported configured service.

Updates must verify a manifest and package hash before staging, preserve rollback, and validate platform/version compatibility. Native OS CI covers Windows, Linux and macOS, with ARM jobs where runners exist. A built-in local acceptance test cannot substitute for unavailable hardware or external services.

## Structure and tests

Focused modules communicate through exported functions and injected clocks/processes/fetch. Root owns UI integration and shared engine; independent agents own workspace, operational and model modules. No npm runtime dependencies. Test real files, child processes and loopback protocol fixtures. Run the combined suite on Windows and root Linux, then real native terminal acceptance. Deliver versioned Windows and cross-platform archives with checksums, a readable guide, and a feature-by-feature evidence table. External services are configured by the user, never claimed provisioned by this build.
