# Workspace acceptance and defensive review

The CLI records bounded before/after checkpoints around native AI tasks. `/changes` shows actual recorded file changes. `/undo` restores only files whose current contents still match the recorded AI result; later edits, replacement files, symbolic paths and unsafe parents become conflicts. New recorded files are individually removed, never recursively removed. Checkpoints are stored privately per canonical project under the configured state directory and survive restarting the CLI. An unfinished checkpoint cannot be undone because its final AI result was never recorded.

`/verify` runs checks explicitly selected by the user. Each check captures its exit code, stdout, stderr, elapsed time, cancellation and limits. A model saying it finished never sets Verified. Zero checks means Needs review. Nonzero exit or a launch error means Failed. A timeout, cancellation, output limit, source change during the checks or incomplete source coverage means Needs review. Verified means those selected checks passed for the recorded source state; it does not prove untested behavior or external service state. Saved evidence is invalidated when the inspected source changes or undo changes the checkpoint. Output previews saved with a checkpoint are bounded; the live result contains the configured capture size.

CLI verification and background acceptance use the same native OS sandbox policy as model commands. Read-only prevents writes; project scope restricts writes to the project and selected folders; Web Off denies networking. The child environment excludes unrelated credentials. A sandbox launch failure fails the check; it never retries directly on the host. Unrestricted checks require full scope, Allow Everything and Web On together. Background tasks wait for acceptance: failed selected checks fail the job, and uncertain selected checks block it for review. Without selected checks, the model result remains Needs review.

Default checkpoint coverage is at most 2,000 files, 1 MiB per file and 16 MiB total, with a 20,000-entry traversal bound and 32 directory levels. Twenty checkpoints are retained; the oldest finished checkpoint is retired when necessary. The configured state directory is excluded even when it is inside the project. Runtime/upstream binaries, Git metadata, dependency caches, credential folders, `.env` files and common private-key files are excluded. Oversized, inaccessible or symbolic entries are reported as omissions. Partial scans conservatively refuse to infer added or deleted files from omitted coverage. Diff output is bounded and credential-filtered. Checkpoints retain original bounded file contents locally for undo; they are not model transcripts or portable exports.

`/workflow` chooses plan, edit, test or review guidance for the normal native session. `/team` runs up to two distinct independent roles, planner and reviewer, sequentially. Each independent role gets a fresh native session and its own disposable, credential-filtered source copy outside the original project. It forces read-only scope, Ask, Web Off, Computer Off, no MCP servers and denied approvals. `AGENTS.md` is preserved under a different filename as source evidence, preventing it from becoming the independent session's automatic instructions. The reviewer can receive a bounded recorded task diff. An explicitly selected source path never widens to unrelated project files or checkpoint diffs. Role results are advisory and never accept work or set Verified. These copies and native read-only permissions are not a virtual machine or a guarantee about every possible filesystem read on the host.

`/security` performs a local defensive heuristic scan. It examines credential patterns without returning values, source sinks such as dynamic evaluation and shell execution, and package declarations such as unconstrained versions, plaintext dependency URLs and install scripts. It runs no scanned code, installs no dependencies, attempts no exploitation and contacts no advisory service or remote target. Findings need validation; no findings do not prove security. An explicitly approved relative local source file or directory can be copied into a bounded disposable lab for defensive review. URLs, path escapes, secret paths, symbolic targets and unresolved approval objects are refused.

## Integration API

`await createWorkspaceTools({cwd, stateDir, secrets, ...limits})` returns `beginCheckpoint(label)`, `completeCheckpoint(id)`, `listCheckpoints()`, `reviewCheckpoint(id, {maxDiffBytes})`, `undoCheckpoint(id)`, `runChecks(checks, options)`, `acceptWork({checks, checkpointId, ...options})` and `getVerification(checkpointId)`. `secrets` is a function returning current in-memory keys. Check objects are either `{command, args, label?}` or `{shellCommand, label?}`. Argv checks launch without a shell; explicitly selected shell text uses noninteractive PowerShell on Windows or `/bin/sh` on Unix. Options include `signal`, `timeoutMs`, `maxOutputBytes` and an explicit environment. Defaults allow at most 16 checks, 120 seconds per check and 256 KiB total captured output per check. Cancellation/limits terminate the owned process tree on Windows or process group on Unix.

Product callers use `acceptSandboxedWork({workspace, settings, checks, checkpointId, signal, timeoutMs, maxOutputBytes})` from `sandbox-checks.mjs`. It supplies the trusted `commandWrapper` hook, isolated environment and temporary native configuration. The lower-level workspace API alone does not enforce a model permission policy. On Unix a fixed Bash/cat bridge supplies ordinary output pipes; selected command arguments stay positional and run inside the native sandbox. On Windows unavailable enforcement returns Failed without an unrestricted fallback.

`createWorkflow({cwd, workspace?, connectionProvider, settingsProvider?, runtimeProvider?, secrets?, snapshotOptions?})` returns `setMode`, `promptInstructions`, `snapshot`, `runReviewer` and `runTeam`. Reviewer/team options include `path`, `focus`, `task`, `connection`, `settings`, `runtime`, `signal`, `timeoutMs`, `maxOutputBytes` and `onEvent`. The default role timeout is 120 seconds and returned output is capped at 128 KiB. `runtimeProvider({role, connection})` is invoked separately for every role; it may return native runtime options and provider request accounting hooks. The caller owns budget task creation/finalization. Explicit per-call runtime options override provider defaults.

`scanWorkspace({cwd, path, signal, ...limits})` returns redacted findings, coverage and limitations. `resolveSecurityTarget({cwd, path, approved:true, label?})` (also exported as `approveSecurityTarget`) returns a resolved local target. `createSecurityLab({target, ...snapshotOptions})` returns its owned `cwd` and `cleanup()`. `createWorkspaceSnapshot` and `collectWorkspaceFiles` provide the underlying bounded copy/walk APIs. Only the latter returns raw local source bytes; every model-bound copy and displayed diff passes through credential and terminal filtering.

Meaningful tests exercise actual files, restored/deleted/added files, human-edit conflicts, corrupt paths, symbolic storage replacement, partial coverage, real child exit/timeout/output/cancellation and descendant termination. Native protocol fixtures verify new sessions, read-only policy and denied approvals. An actual installed native Codex test verifies that a budget refusal happens before the independent reviewer reaches its loopback model endpoint. No paid endpoint, external target, vulnerability database, physical hardware or native macOS runtime is used by those tests.
